# 图片上传

图片上传配置由整个 EasyMD 共用，不随知识库切换。已有 Markdown 中的图片链接不会自动迁移。

## 上传方式

- 本地附件：默认方式，图片存入当前知识库的附件目录。
- S3：直接上传到兼容 S3 的对象存储。填写 Endpoint、Region、Bucket、Access Key、Secret Key、公开访问地址和路径前缀。Endpoint 用于 API 请求；公开访问地址用于生成写入 Markdown 的长期图片链接，二者可以不同。路径模式用于 MinIO 等服务，虚拟主机模式用于要求 bucket 子域名的服务。
- PicGo：先安装并启动 PicGo，在 PicGo 中配置图床并开启 PicGo-Server。默认地址为 `http://127.0.0.1:36677/upload`。EasyMD 通过本机服务上传图片，使用 PicGo 返回的链接。Gitee 等图床的插件、令牌与仓库配置在 PicGo 中完成。

S3 Secret Key 由系统凭据存储管理，不写入知识库。切换上传方式会保留其他方式的配置。保存与测试不会改写已有笔记。

## 插入图片

在笔记编辑器或随手记中粘贴图片，或使用「插入图片」选择文件，也可以将图片拖入编辑区。支持 PNG、JPEG、GIF、WebP、BMP、ICO，单张最多 20 MiB。

上传失败时，队列保留图片，可重试、改存本地附件或取消。上传期间切换笔记不会把结果插入另一篇笔记；回到原笔记后手动重试插入。取消已发出的上传不会删除可能已创建的远端对象。退出应用后不会保留待处理队列。

画布的图片文件节点继续使用本地附件。

## 测试

「测试上传」会上传一张小图片，检查返回的图片地址，并报告测试对象清理情况。测试会实际创建远端对象。PicGo 的通用上传接口没有删除接口，测试图片需要在图床中手动清理。

公开分享需要可直接访问的图片地址。私有存储桶或有时效的签名地址不适合长期写入笔记；上传成功也不等同于公开地址可访问。使用 Gitee 时应实际检查其返回地址在分享页面中的访问情况。

删除笔记或图片引用不会自动删除远端对象。

## PicGo 接口参考

使用 PicGo 2.2.0 起提供的 HTTP 上传接口：`POST /upload`，JSON 请求体为 `{ "list": ["本机图片路径"] }`，成功结果为 `{ "success": true, "result": ["图片URL"] }`。EasyMD 仅连接本机 PicGo 服务。

官方说明：<https://picgo.github.io/PicGo-Doc/zh/guide/advance.html#picgo-server的使用>
